真实图片 OCR 持续优化实验计划

日期：2026-10-21。状态：计划已制定；尚未准备新训练数据、实现循环控制器或启动第三轮训练。

目标：在预先约定的真实文字裁图分布上，让固定版本的微调模型可靠地优于原始 PP-OCRv5 mobile 底模。由助手完成数据、训练、评测、复核和逐轮报告。仍只测裁图识别，不把结论扩大到整图文字定位或 Language Bubble 的全部使用场景。

1. 先固定目标、对照和成功条件

  • 底模固定为 PaddlePaddle/PP-OCRv5_mobile_rec_safetensors，revision 485a9a9781535ad477de3b1eea5f96a2e7300d8d，以文件 SHA256 再确认。保留已有底模和两轮模型。从原底模开始新的真实数据实验，不默认接着已退步的第二轮模型训练。
  • 初始目标分布沿用上一轮公开真实图测评：英文街景 50%、中文/混合街景 25%、中文/混合网页图片 25%；合计英文 50%、中文 30%、混合 20%。网页图片不等于真实应用截图。可在第一次新实验前，因数据可用性修改一次分布并登记；开始循环后不得为了成绩改变分布。
  • 两模型同图、同裁切、同预处理、同解码和同评分。模型推理使用 CPU、2 个 intra-op 线程、1 个 inter-op 线程。增强只进入训练，不对候选单独增加旋转、超分辨率、词典或语言纠错。
  • 本阶段正式主指标预注册为“格式归一化后的整段完全正确率”：双方答案均做 Unicode NFKC、casefold、去空白，保留标点、不做简繁转换。选择这一口径是因为已知公开标签存在大小写/空格惯例差异，不是根据新实验成绩挑指标。必须并列报告严格正确率、严格 CER、归一化 CER；格式能力不能由归一化得分代替。
  • 结束循环须由最终确认测试支持：同一个锁定模型在两批全新确认题上均比底模正确率高，合并正确率至少提高 2 个百分点，主指标通过下述重复尝试校正后的配对检验，合并归一化 CER 下降，严格 CER 不恶化。任何条件不满足，都不宣布成功。
  • 预注册英文、中文、混合和三类来源的分组结果。若任一组的归一化正确率下降超过 2 个百分点，或归一化 CER 增加超过 1 个百分点，不接受为覆盖本计划全部分布的升级。此规则只是观察值护栏，不等于统计证明每个分组都没有退步；分组区间不充分时明确标记。

2. “每次测试用全新数据”的执行定义

  • 每轮使用新的验证批次 V_i 和新的阶段测试 T_i。同一次评测中，底模与候选必须用同一批题；同次验证可同时比较事先列出的有限个检查点，避免拿不同题的绝对分数选模型。
  • V_i 用于选检查点，T_i 在检查点锁定后用于诊断本轮泛化。它们不能互相替代。为充分满足换题要求，不按每个 epoch 重复看同一验证集：先完成固定的短训练并保存候选，再在一个新的 V_i 上集中比较一次。训练损失可持续记录。
  • 已看过、算过分或指导过决策的评测图片，一律登记为已使用。后来只能作为历史错例/回归资料；本循环不再用它们充当新的验证、阶段测试或确认测试，也不加入梯度训练。
  • 同原照片、页面、拍摄连拍、同图不同裁切，以及增强变体，属于同组，不能跨训练和评测划分；不同轮评测组之间也不重复。图片文件哈希、解码后像素哈希、感知近重复和来源 ID 联合查重，并审查疑似重复。
  • “新数据”不靠换文件名、换裁切或给旧图加噪声实现。不同真实图片出现同一个常见单词是正常的，不人为删除所有相同文字来改变数据分布；疑似同一内容模板或同场景图片需分组处理。
  • 同一实验内，为排查实现错误而重载模型、复算已保存的预测/指标，标记为技术复核，不算第二次独立测评，也不产生新的泛化证据。
  • 只能保证独立于本地微调和已开展评测；公开数据是否进入过底模预训练目前未知。

3. 数据准备：真实训练数据与一次性评测题池

先登记来源、官方版本、许可/使用条件、训练与测试 split、标签约定和原图组 ID，再下载选定的小部分。优先重用环境和读取工具，不重新下载模型。

用途 初始预算 使用规则
真实训练集 约 2,000 张 来自官方训练 split；按预定分布采样；可多轮使用
每轮新验证 V_i 约 300 张 对同次所有候选与底模配对比较；只用于本轮选择
每轮新阶段测试 T_i 约 400 张 验证后只比较底模与一个已锁定候选；看过即退役
最终确认 F_k-A、F_k-B 初始各 800 张 不参与选择；同一候选同时锁定两批；两批跑完才解释结果
  • 以上数量是准备预算，不是已获取的数据或保证充足的统计功效。首次正式确认的样本量在开启题目和预测前，依据旧结果/开发数据中的配对分歧率、2 个百分点的目标差异、显著性预算和 80% 功效目标计算并锁定；如果需增加，则先核对资源。不能看了确认成绩再追加题直到显著。
  • 原有约 450 张合成图和 200 张真实测评图保留为历史资料，不计作新题。现有 BCTR/ICDAR 官方 test 下载不作为新训练数据来源。
  • 现有散裁图缺少原照片 ID，不能仅靠随机分图就宣称分组独立。正式确认优先使用能恢复原图 ID 的数据，每个原图组固定随机抽一张裁图；无法可靠确认分组的材料只能用于探索，不能悄悄放宽正式验收。
  • 单独建立尚未解封的确认题池；尽可能覆盖不同采集来源，并在各来源内按组隔离。整个题池清单与分配种子先锁定，用原图组信息防止训练数据和后续测试池交叉。题池耗尽时先补充合格的新来源，不循环抽已用题。
  • 在查看模型预测前做标签质检，记录空标签、不可辨认文字、坏图和疑似错标的处理规则及排除日志。最终确认标签逐张核对，阅读不确定的样本按预定规则处理，真值不由待测模型或其他 OCR 的输出直接替代。保留原标注与所有修订记录。
  • 不因图片模糊、竖排、底模识别错误或超出常用字符而筛掉难题。训练侧如因损失/长度约束必须排除样本，提前定义并单独报告，测试侧不随之删除。

4. 第一批训练实验：先解决最有证据的问题

前三个方向按结果推进，每轮配置在读取新验证/测试结果前写入协议。每轮只保留少量预先指定候选；跨轮不能比较不同题上的绝对分数来评冠军。

轮次/条件 主要改变 目的
A：真实数据起点 从原底模出发，约 2,000 张真实训练图；仍只训练最终分类层；AdamW、lr 2e-5、weight decay .001、batch 1、clip 1.0；固定第 1/2/3 遍候选 先验证把训练内容换成真实图片，是否产生可迁移的收益
B：A 有收益也有原本正确样本退步 保持训练集、种子、层、轮数和其他设置，学习率降至 5e-6；本轮新验证同时评估 A 的锁定版本作为参考 检查较保守的参数更新能否减少误改；先不叠加其他改动
C：依 B/A 错误分布选择一个方向 若某类图覆盖不足，只补充同类的全新训练 split 样本/调整训练采样；若各类都出现误改，则单独试约束参数偏离底模的正则化 用证据决定下一次干预，不把加数据、加轮数、解冻模型一次全混在一起

C 的具体采样配额或正则化公式、强度必须先写入新一轮配置再运行，不留成事后自由挑选的参数。如果早期候选已满足开发门槛，可直接进入最终确认，无需为了凑轮数把 A/B/C 全跑完。

第一批先保持图像骨干与编码器冻结，使用有限大小的特征缓存。只有真实数据和保守微调仍无效、且错误分析指向特征表达不足时，才设计解冻最后一个编码模块的独立实验；必须重新短测兼容性、内存与时间，再确定可行配置，不能沿用冻结特征缓存冒充解冻训练。

A 同时改变了相对于旧合成实验的数据和短训练日程，属于新的改进起点，不能单凭 A 的结果断言二者各自的因果贡献。B 等受控比较才用于分辨具体策略。

5. 每轮固定流程

  1. 写下本轮假设、唯一主要干预、数据分组与哈希、随机种子、优化器、训练层、候选检查点、最大更新数、评分及资源预算。配置和脚本快照落盘。
  2. 查重、核对标签和磁盘余量；短测前向、反向、真实参数更新、保存、重载与断点恢复。正式评测数据不进入这一步的调试。
  3. 在约定预算内训练。记录训练损失、已完成步数、耗时、内存与磁盘；不以“测试刚好变好”为训练停止依据。
  4. 解封全新 V_i，在同一批图片上比较底模与预注册候选，以归一化 CER 最低选择；并列时选更新较少者，底模也参与比较。若候选都未胜过底模，则不消耗阶段测试题，直接记录开发失败并设计下一轮。
  5. 锁定所选模型和预处理器哈希，再解封全新 T_i。评测底模与一个候选，计算严格/归一化整段正确率、CER、改对/改错数量、来源/语言分组和资源成本。阶段测试胜出只叫“出现候选收益”。
  6. 独立复算全部指标，抽查重载后的完整模型预测；保存全部题图、标签、双方输出，以及改善/退步/仍错的分类。
  7. 若阶段测试主指标改善且 CER、分组护栏方向可接受，进入最终确认；否则按主要错误类型决定下一轮。下一轮重新使用 V_(i+1)、T_(i+1)，不能靠旧测试调出一个好结果。

若要比较上一轮模型和本轮模型，必须把上一轮作为提前列出的参考，在本轮同一新验证批次中重测；不拿上一轮 60% 与本轮另一套题的 62% 直接推断本轮模型更好。

6. 最终确认：防止“试到偶然赢一次”

持续训练并看新题成绩属于自适应探索；换题可以防止直接记住题，但不能自动消除重复尝试导致的假阳性。因此单独设置正式确认步骤。

  • 进入第 k 次确认时，锁定一个模型、两批新题的样本量/来源配比、评分及检验程序。不得用 A 批选模型或调整处理方式后再测 B 批；两批属于一个预注册确认实验。
  • 主指标使用同图配对的单侧精确 McNemar 检验，检验候选正确率是否高于底模。正式样本按原图组独立抽一张；不能用大量同图裁剪虚增样本数。分层比例固定；报告配对差值区间并注明目标分布。
  • 整个优化过程的确认显著性预算使用 alpha_k = 0.05 / 2^k，从 k=1 开始：第一次 .025，第二次 .0125，第三次 .00625。所有确认尝试永久累计，不按批次重置；预算总和不超过 .05。前提是每次题组独立、候选在看新题结果前固定。
  • 成功同时满足第 1 条中的实际收益、检验和护栏。两批某一批下降、效果不够大、统计证据不足、格式质量退步，均如实记录为“尚未确认”，不更换评分口径补救。
  • 确认失败后，两批题退役，计入历史记录；可以分析错误指导新的开发轮次，但下一次确认必须使用两批完全新数据，并消耗下一档显著性预算。
  • 此方法控制反复验收的偶然通过风险，不能消除数据错标、来源偏差或未知底模预训练重叠。结论只适用于计划覆盖的真实裁图分布，不泛称所有中英文 OCR 都改善。

7. 循环边界、时间和资源

循环逻辑：预注册本轮 → 准备真实训练数据 → 短训练 → 新验证选模型 → 新阶段测试 → 错例分析 → 修改一个主要因素 → 下一轮；满足开发门槛则插入两批新题正式确认，确认成功后保存胜出模型并结束。

目标是通过验收，不能保证有限轮数内一定达到。先按最多 3 个开发轮次为一批安排计算，每批结束汇报已验证的假设、成本和下一批方向。分批是复盘/预算节点，不把未达标改称成功；有合理假设与足够资源才继续。若连续 3 轮没有新的改善信号，先重新检查数据代表性与可训练层限制，不机械增加训练次数。

  • 当前 df 约有 19 GiB 可用空间；沿用至少 10 GiB 系统余量。新阶段数据、缓存、检查点、报告和原子保存临时副本的合计新增峰值上限先设 3 GiB，不是每轮都可新增 3 GiB。后续题池分批补充，避免预先下载大型完整训练库。
  • 默认 CPU 两线程、无额外数据加载进程、各实验串行。初始进程内存目标不超过 3 GiB，特征分块计算与读取；实测超出时缩减缓存/配置。先沿用已验证 CPU 路径，GPU 不作为本轮提升来源或必要前提。
  • 每轮特征准备、核心训练及保存先预算 20–45 分钟；训练窗口给保存与退出留缓冲。正式训练工作量由新数据的短测确定，不承诺新数据和旧 300 图一样快。
  • 首次新数据准备、标签质检与流程补齐粗估 1–3 小时；每轮分析/新评测约 10–25 分钟；两批最终确认及复核粗估 15–40 分钟。第一批完整工作暂按 3–8 小时规划，下载、标签质量、原图分组恢复会影响耗时；实际计算时间与端到端人工核查时间分别记录。
  • 开始前实现并验证：原子检查点保存、真实断点续训、磁盘写入预算、资源采样和有序停止。旧脚本仅保存状态、没有完整恢复入口，不能声称已有自动续训保障。断点需记录优化器、随机数状态、采样顺序和步数。
  • 已有底模、旧模型和历史结果不覆盖。新轮次至少保留选中模型、该轮配置和完整预测；临时缓存/未选检查点按事先登记规则回收，只处理本次新循环生成的可重建文件。
  • 资源不足、样本池不足或故障时保存状态、报告具体原因并停止本次计算；先缩小可重建缓存或补齐数据/流程，不消耗安全余量硬跑，也不修改用户应用和系统配置。不能保证任何 Mac 进程永不中断。
  • 不创建后台定时任务或假定新的饭点窗口；执行时遵循用户当前的可用窗口。此次请求交付计划，不启动循环。

8. 每轮交付与最终产物

每轮提供：一句话结论、与底模同题比较的分组指标、全部原始预测、改善/退步实例、假设是否得到支持、下一轮唯一主要改动、时间/内存/磁盘消耗，以及失败与异常记录。保留失败轮次，不只展示最好的一次。

计划目录约定：runs/real_loop/round_NN/ 保存协议、代码快照、配置、哈希、状态、预测和复核；data/real_loop/registry.jsonl 登记数据分组和已使用状态；models/real_loop/round_NN/ 保存候选；reports/real_loop/ 保存逐轮报告与确认记录。这些目录/控制功能尚未实现。

最终只有通过预注册确认，才交付标注为“在本计划真实裁图分布上验证优于底模”的模型。报告注明增益、置信范围、适用场景和未解决问题；如果尚未通过，就明确保持“仍在优化/尚未证实改善”。
